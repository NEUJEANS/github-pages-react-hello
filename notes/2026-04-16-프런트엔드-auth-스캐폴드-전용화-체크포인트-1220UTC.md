# 2026-04-16 프런트엔드 auth 스캐폴드 전용화 체크포인트 (1220 UTC)

## 이번 슬라이스의 한 줄 목표
현재 auth-entry 프런트엔드 표면은 유지한 채, 백엔드/런타임 포인터 중심 auth 전송 레이어를 프런트엔드 스캐폴드 전용으로 잘랐다.

## 이번에 실제로 한 일
- `src/components/auth-submit.js`
  - 원격 fetch / runtime auth base / same-origin fallback / loopback probe 힌트 같은 backend-oriented 전송 분기를 제거
  - 공개 API 이름은 유지하면서 내부를 모두 frontend scaffold 어댑터로 단순화
  - 로그인 / 회원가입 / continuation / session / pending / logout 경로가 모두 같은 same-origin scaffold 계약으로 정리됨
- `src/components/auth-flow-state.js`
  - 서비스 오류 문구에서 GitHub Pages runtime wiring / 공개 authApiBaseUrl / loopback 안내를 제거
  - 현재 의도에 맞게 frontend-only auth demo 실패 문구로 축소
- `src/components/auth-config.js`
  - `apiBaseUrl`, `currentOrigin`, `allowLoopbackProbe`, `loopbackProbeBlockedReason` 같은 backend-era 필드를 현재 프런트엔드에서 쓰는 최소 계약으로 축소
  - `resolveAuthConfig()`가 이제 app base path + same-origin auth endpoint 집합만 돌려주도록 정리
- `src/app-shell.jsx`
  - 인증 완료 후 세션 재조회 경로에서 낡은 runtime source 라벨 강제 주입을 제거하고 `authConfig.source` 기준으로 정렬
  - 더 이상 쓰지 않는 backend-style auth config 필드를 넘기지 않도록 정리
- 테스트 정리
  - `src/components/auth-submit.test.js`
  - `src/components/auth-flow-state.test.js`
  - `src/components/auth-storage.test.js`
  - `src/components/auth-wiring-state.test.js`
  - 기존 backend/remote 기대치를 frontend scaffold baseline에 맞게 재정렬

## 이번 변경의 의미
- auth-entry UI는 그대로 두고, 내부 transport만 정리했기 때문에 **현재 프런트엔드 제품 표면을 되돌리지 않았다**.
- auth 흐름은 이제 “실제 백엔드 복구 중”처럼 보이는 다중 모드 구조보다, **지금은 프런트엔드 스캐폴드**라는 사실에 더 정직한 구조가 됐다.
- 나중에 더 나은 백엔드를 다시 연결하더라도, 연결 지점이 지금보다 좁고 명확해질 기반을 만들었다.
