# 2026-04-16 프런트엔드 셸 죽은 흐름 정리 체크포인트 (1132 UTC)

## 이번 슬라이스의 한 줄 목표
현재 프런트엔드 표면은 유지하고, 로그인/페이지 전환을 깨뜨리는 죽은 레거시 셸 연결만 먼저 제거했다.

## 이번에 실제로 한 일
- `src/app-shell.jsx`
  - `openLogin()` 안에 남아 있던 `setSearchDrawerOpen(false)` 호출 제거
  - 이미 제거된 검색/브라우징 표면의 잔재라서 현재 로그인 진입 시 런타임 오류 원인이 될 수 있었음
- `renderScreen()` 정리
  - `AiRecommendPage`에 더 이상 존재하지 않는 `styleOptions`, `priorityOptions`, `lifestyleOptions`, `Header` 의존 제거
  - `BedsCategoryPage`, `FurnitureHomePage`에 더 이상 필요하지 않은 `Header`, `aiProducts`, `bedProducts` 전달 제거
  - `LayoutEditorPage`에 남아 있던 `Header` 전달 제거
- 결과적으로 현재 3페이지 분리 이후 남아 있던 죽은 props / 죽은 함수 참조를 잘라서
  - 레이아웃 보드 진입
  - 로그인/회원가입 모달 진입
  - 은퇴된 페이지(surface) 렌더링
  경로가 모두 현재 프런트엔드 기준으로 더 안전해짐

## 왜 이 슬라이스를 먼저 했는가
- 사용자 지시의 핵심은 **백엔드 복구가 아니라 현재 프런트엔드 상태 유지 + 복잡한 결합 제거**다.
- 방금 제거한 것들은 실제 사용자 플로우를 깨뜨릴 수 있는 죽은 연결이었다.
- 검색/브라우징/옛 페이지 전달값은 이미 프로젝트 범위 밖으로 밀려난 표면이라, 먼저 잘라내는 편이 React 셸을 얇게 만드는 데 직접적이었다.

## 검증

## 현재 관찰
- `main.jsx`는 이미 얇은 엔트리 역할만 수행 중이다.
- 하지만 `src/app-shell.jsx`는 아직 너무 크고, auth/session/layout 복합 상태가 많이 남아 있다.
- 특히 auth 쪽은 실제 네트워크 백엔드보다 프런트엔드 스캐폴드로 돌아가고 있어도,
  상태/헬퍼 이름과 계약은 아직 backend-oriented 흔적이 많다.

## 다음으로 가장 직접적인 슬라이스 후보
1. `auth-session-view-state.js`에서 UI가 실제로 쓰지 않는 backend contract/payload preview/connection 설명 상태 제거
2. auth 에러/상태 카피를 GitHub Pages runtime/backend 안내 중심에서 frontend-only 흐름 중심 문구로 정리
3. `app-shell.jsx`에서 auth 관련 거대 상태를 별도 page/session 모듈로 옮겨 셸을 더 얇게 만들기
4. apartment selection/search 잔존 상태(`apartmentSearchResults`, `spaceProfile` 일부)가 실제 현재 표면에 꼭 필요한지 재검토 후 축소

## 유지해야 할 원칙 재확인
- 현재 프런트엔드 표면을 baseline으로 유지
- backend auth 복구/터널 갱신/라이브 포인터 수선에 메인 시간을 쓰지 않기
- auth UI는 프런트엔드 전용/재연결 가능한 구조로 단순화
- apartment exploration/search/browsing 잔재는 계속 제거 대상
